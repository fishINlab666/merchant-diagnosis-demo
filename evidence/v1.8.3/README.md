## 失败保留与修复

1.8.1新跑曾因合法证据超过100条卡住；1.8.2扩到1000条但仍逐来源验证，其他数组不放宽。复核原先继承分析的思考设置并耗尽输出，现独立配置并读取本轮冻结流程。

1.8.2单店与连锁、反证、录像均通过对应验收，但API两轮没有完成交付：Flash在修订时返回无效计算JSON；Pro第一次主金额计算未实际引用变量，自动变量化重算又复用旧编号，被仅一次格式纠正额度提前拦住。API复核也曾混淆基准与审慎场景，独立原件重算没有照错误意见改账。

1.8.3针对这些真实失败增加第二次有上限的格式纠正和明确的新编号提示。总调用仍最多8次，业务修订一次，截断/网络/复核错误不静默重试；无效请求不执行，原计算不覆盖。保持来源和独立复核门禁。最终包重新生成，不将1.8.2的视频重新贴成1.8.3。

本轮原生会话曾发生连接超时自动重连，具体次数见运行摘要，不宣称零重试。首轮1.8.3连锁报告业务通过，但录像辅助检查将“取消通用券”误认为没有“不补贴”选项，在展示尾段前中止；该原片保留，修正录像检查后重新从上传材料开始录制。第二轮Agent自查并在新目录交付了订单合计修正版，但录屏服务仍固定打开首稿；独立核对拦住该视频。修复服务使其选择宿主明确交付且通过完整性核对的最终报告，报告与冻结打法共用同一路径，再重新录制第三轮。

原生Agent模式的model_calls=0只表示脚本未另发API，不代表没有模型分析。允许模型自行纠正，最终通过仅证明这些实际运行，不承诺任意输入或模型都零返工。原始失败稿/原片/完整会话在本地保留，公开证据不包含私人路径、凭证或模型推理原文。
