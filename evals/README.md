# 商户预算诊断 Demo EVALS

## 评测目标

验证工具是否把过往业务方法变成可重复的产品行为，而不只是生成一份看起来合理的报告。当前首条链路不使用外部模型，因此本评测针对**确定性规则、测算、数据质量、角色输出和执行闭环**，不声称评估了 LLM 的通用诊断能力。

## 依据

1. 原始产品设计书：同口径计算、归因成熟度、利润风险、候选原因边界、行动停止条件和数据质量阻断。
2. 过往业务方法：保留基本盘、增量预算向高效率工具倾斜、UE 与增速同时看、分层配置资源、看板必须触发执行。
3. 最新一页需求：三步工作流、一份周报、四块输出、三类角色、多份合成数据和真实执行验收。

## 用例结构

- **历史方法：**预算调整方向、保留基本盘、利润为负时不鼓励追加。
- **测算：**挪移与追加分开、假设变化可重算、零金额不生成动作。
- **数据质量：**归因定义／窗口／成熟度、整体与工具指标分离、负数和重复数据。
- **输出与角色：**公开信息不提前下结论、角色话术、问题数量和禁用承诺。
- **执行闭环：**负责人、指标、日期、停止条件、基线／对照。

## 通过口径

- 当前版本的 20 项均为阻断性用例，必须全部通过才能进入 review gate。
- `results.json` 记录实际通过率和每项证据，不能用文档目标替代运行结果。
- 门店分层、多平台归因和真实商家成效不属于当前单店 demo 的已交付范围，在业务评分卡中单独标记为后续验证，不混入当前通过率。

## 运行

```bash
npm run evals
```
