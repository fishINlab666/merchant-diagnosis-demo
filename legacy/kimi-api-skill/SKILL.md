# 商户诊断

## 必须遵守

- 必须执行真实模型调用。公开初诊、表格语义映射和完整方案三个阶段都使用 Kimi，不得用固定文案替代。
- 必须让程序读取原始单元格并复算数字。模型只解释数据和给出建议，不得自行补写缺失值。
- 必须保留模型名、调用次数、token 用量和映射缺口。调用失败就停止并报告错误，不得伪装成成功。
- 必须使用合成或脱敏数据测试。上传真实数据前提醒用户数据会发送到所配置的 Kimi API。
- 必须按“初步判断 → 为什么值得继续 → 需要哪些数据 → 完整方案”组织客户沟通，边界提醒集中说一次。

## 执行

1. 阅读 [references/methodology.md](references/methodology.md)，确定公开事实、内部数据和客户表达的边界。
2. 阅读 [references/schemas.md](references/schemas.md)，了解标准字段与输出结构。
3. 运行：

```bash
python scripts/diagnose.py \
  --public-file assets/public-shop.txt \
  --files assets/demo-weekly.csv \
  --out output/merchant-run
```

只用公开信息时省略 `--files`。公开文本也可用 `--public-text` 直接传入。输出目录由用户指定，不要覆盖已有结果。

## 输入什么

### 必需：店铺页公开信息

通过 `--public-file` 或 `--public-text` 提供。可以包含店名、平台、城市／商圈、品类、评分、月售、人均、起送价、配送费、配送时长、菜单、价格、评价原文，以及明确提供的竞店信息。没有的数据不要补写。

### 可选：一份或多份经营数据表

通过 `--files` 提供 CSV／XLSX，可包含多个工作表、门店汇总表、流量表、投放工具明细表、补贴表和用户表。允许不同中英文表头，由 AI 判断表粒度和字段语义，不先写死别名。

- 只用公开信息时省略 `--files`，只执行公开初诊。
- 多门店文件先按门店分别运行，不混合计算。
- 真实商家数据上传前，提醒用户数据会发送到所配置的 Kimi API；测试只用合成或脱敏数据。

## 分几步分析、每步输出什么

### 第一步：公开初诊——先让商家觉得“你懂他的生意”

**输入：**店铺页公开文本。

**AI 工作：**识别具体问题及业务价值，区分公开事实与待核查假设，不使用内部 ROI、利润或预算结论。

**输出 `public-diagnosis.md`：**

- 一个有业务判断的标题。
- 最多 3 个“公开证据 → 为什么重要 → 下一步核查”的观察。
- 为什么值得继续提供周报。
- 下一步数据清单及每项数据能回答的问题。

**在哪里提醒客户补数据：**在本文件末尾的“拿到这些数据，就能继续算清楚”区块，按业务问题列出所需数据，不集中说很多免责声明。

### 第二步：AI 表格理解——先确认表格在说什么

**输入：**一份或多份 CSV／XLSX 的原表头、样本行和工作表结构。

**AI 工作：**返回表粒度、原字段到标准字段的映射、单位和歧义。程序随后从原始单元格取数、转换和聚合，模型不直接填数值。

**输出 `mapping-preview.json`：**

- 每个文件／工作表的粒度和字段映射。
- 无法可靠映射的字段、数据质量警告和歧义。
- 门店、周期和工具明细的合并规则。

**在哪里提醒客户补数据：**在 `missing_fields` 和 `canonical_warnings` 中明确指出。多门店、缺门店 ID、缺周期、缺净 GMV、缺工具明细、归因窗口不一致或数值冲突时，必须在继续分析前说明；能降级的模块继续，不能复算的模块关闭。

### 第三步：完整经营分析——用内部数据形成方案

**输入：**公开初诊、AI 映射结果和程序生成的真实门店周报。

**AI 工作：**结合六维方法提出最多 3 个问题、预算建议和动作；程序检查工具名、金额、归因口径并复算，必要时让模型针对校验错误重改。

**输出 `full-diagnosis.md`：**

- 最多 3 个问题及数据证据。
- 预算挪移／追加建议及适用条件。
- 程序复算的 GMV、毛利、消耗和贡献拆解；不能复算时显示阻断原因。
- 给店里的三句话。
- 最多 3 项下周跟进，包含负责人、复核指标、日期和停止条件。

**在哪里提醒客户补数据：**在对应分析模块和复算阻断原因中提醒。缺曝光／进店就不能判断漏斗，缺复购／会员就不能判断留存，缺同口径竞店就不能生成排名，缺归因窗口就不能比较工具 ROI。不得用另一段数据冒充已回答。

### 第四步：交付与运行证据——让客户知道怎么执行

**输入：**完整分析、复算结果和映射缺口。

**输出：**

- `result.json`：结构化结果，供其他产品界面使用。
- `run-metadata.json`：真实 provider、model、调用阶段、token 用量、输入文件、缺失字段和计算警告。

**在哪里提醒客户补数据：**在 `mapping_missing` 和 `warnings` 中保留机器可读清单；在 `full-diagnosis.md` 末尾只保留一处边界说明，说明哪些是情景测算、哪些需要下周复核，不在每张卡片重复。

## 输出文件清单

- `public-diagnosis.md`：公开初诊和数据索取。
- `mapping-preview.json`：AI 表头映射、缺失字段和警告。
- `full-diagnosis.md`：完整经营方案。
- `result.json`：结构化结果。
- `run-metadata.json`：真实调用和计算证据。

若任一模型阶段失败，返回非零状态并说明失败阶段，不输出伪装成功的报告。
