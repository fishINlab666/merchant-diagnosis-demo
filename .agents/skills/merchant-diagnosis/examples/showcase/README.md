# 经营看板示例

两个商家均为合成演示案例，报告来自 Codex 的既有实际分析。`runs/` 中 report.md 保持原字节；execution.json 仅保留实际执行者、模型 ID 和原记录指纹；materials.json 仅保留文件名与指纹，未嵌入原始材料正文或作者本机路径。复制与导出不是新的模型运行。

在 Skill 根目录执行：

```sh
python3 scripts/export_report.py --config examples/showcase/catalog.json --output dashboard.html
```

生成的 HTML 可独立移走、离线打开；JSON 和 manifest 用于核对，不是网页运行依赖。分析新商家时需用新运行目录及其展示配置，不要替换案例名称后继续使用这些数字。

- **30 店预算决策**：默认补数后的更正结论。旧 +32,400 元月度固定成本前贡献情景保留在历史版本；新材料转负后撤回方案，不能把撤回说成已经省钱。只有原版本有 S1/S2；更正版本只重新运行 S3–S5。
- **四店乱格式周报**：只生成 S3–S5。园区成本未知；三店贡献不能冒充四店。相同 90% 的渠道占比没有边际试行证据，因此本轮不自动挪预算。

图表使用通用展示 schema，数字来源及原计算指纹见 `calculation-sources.json`，每个指标与图表另附证据。`build.py` 是此项目维护者从既有运行目录重建展示快照的脚本，需要原项目记录；已打包快照与网页导出不依赖它。所有计算只是合成数据或条件情景，尚无商家执行效果。
