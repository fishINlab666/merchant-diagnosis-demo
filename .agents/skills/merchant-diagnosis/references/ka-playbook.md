# KA 经营打法：把诊断变成资源决策和门店动作

这份方法来自作者在阿里本地生活 KA 工作中的城市/门店分层、人群与菜品权益匹配、工具组合及跨组织推进经验。历史材料是作者经历自述，并非本 Skill 的商家效果证明。原来的平台 UE 分析在这里改写为商户经营贡献；边际约束、行动回执和扩围条件属于本轮产品化补强。

默认分析和独立 API 复核都读取本次冻结的这份文件。**按材料触发相关分支，不让客户填方法表、不强行分四类、不要求所有商家补齐人群或联营政策。**Agent 在同一报告的 `method_usage` 中记录四类方法的适用状态、依据与落点；缺数据/不适用可以正常交付，不强凑采用。

## 1. 先定谁的账，再按收益质量 × 增长决定资源

**原打法：**大区确定方向，作者主导把城市分析下拆到门店，使用 UE × 增速四象限和看板匹配资源。只看品牌均值会把“值得加码”和“需要整改”的店混在一起。

**什么时候用：**连锁有可比门店数据，或单店有可比商品、时段、服务项目。先核同一主体、周期、成熟订单、门店类型和费用范围，再计算可比净收入增长、贡献及单均贡献。原平台 UE 不能直接叫商户利润；租金等固定成本未纳入时明确叫经营贡献。

“好/弱”依据老板目标、同口径可比组或盈亏及趋势，不套历史阈值。零贡献线只区分赚亏，不自动等于优质线。没有目标时可按相对差异选优先级，说明参照；没有成本时把收益质量列为未知，仍分析已知的收入、供给和执行问题。

| 证据支持的门店状态 | 优先决策 | 不应直接做的事 |
|---|---|---|
| 收益质量好，增长好 | 保供给和履约，按新增贡献及容量分批支持增长 | 用平均 ROI 推算无上限加投 |
| 收益质量好，增长弱 | 找流量、目标客群或下单承接中卡住的一段，选对应工具小范围试行 | 因增长慢就削资源；未查原因就增加曝光 |
| 收益质量弱，增长好 | 拆商品让利、变动成本、广告和履约；先修单均贡献，协商真实可用资源 | 把订单增长当成功，继续花钱买低贡献订单 |
| 收益质量弱，增长弱 | 先修可控的商品、营业、库存、服务或履约问题，出现恢复信号后再测增长 | 全品牌统一加投，或只因暂时低迷就永久退出 |

**怎样落到输出：**给出“哪类店/哪几家 → 主矛盾 → 保留/调整的资源 → 第一动作”，在 findings/actions/analysis 中按需表达。贡献好但增长差与贡献差但增长好不能拿到同一张调预算建议。仅观测部分店就限定范围，不乘总店数外推。

**何时补数：**只有品牌总表时，索取会改变资源分配的门店净收入、已确认成本口径和营业/履约数据；缺其中哪项就说明无法决定哪类店该加码。老板已给的成本比例直接算，不再索整套财务报表。

## 2. 从城市继续拆到客群、场景和履约条件

**原打法：**不同市场的主要矛盾不同；城市颗粒度仍可能让策略到了店里失效。作者按城市和门店差异匹配工具、组货与协同。

**怎么判断：**出现城市/门店差异时，用本次材料中的商圈需求、时段、客单、竞争、库存、营业和配送条件解释差异。只保留会改变动作的分组，例如午餐高峰缺货店先恢复供给，供给稳定但进店少的店才检验触达。不能凭城市名字猜白领、学生或价格敏感度。

**输出：**用一句完整因果链说清“这组店的需求/承接特点 → 当前瓶颈 → 商品或工具选择 → 执行人”。遇到直营与加盟、不同区域权限时，先确认谁能改价格、库存、排班和投放，不默认总部能下令全部店。

**补数与反证：**没有时段/客群数据就不编画像；仅补影响选店或工具选择的切片。若更正后缺货/营业差异消失，应撤回该归因，转查仍有证据的成本、商品或触达问题，不能保留“整改供给必然有效”的原结论。

## 3. 人群 × 商品 × 权益：既看买得贵不贵，也看钱花在谁身上

**原打法：**作者主导频次（一单、二单、多单）与生命周期（潜客、新客、留存、流失召回）分层，使用平台现有人群包，匹配菜品权益并复盘。平台提供数据与投放能力，品牌落实商品和套餐；这不是自建 RFM 或 CRM 系统。

**什么时候用：**材料有触达、进店、下单或人群结果，且问题涉及获客、转化或复购。无投放单店也可按真实顾客需求检查商品/服务承接，不强套人群广告。

- 曝光到了、进店弱：先检查目标客群与表达是否相符；不能先认定商品必须降价。
- 进店有了、下单弱：查商品、价格、规格、套餐、权益及库存；增加曝光可能只是放大流失。
- 有同口径分群结果：比较每群净收入、商家承担让利、商品/履约成本和广告，明确拉新、复购或召回目标，再选群与权益。高频客不自动值得补贴，老客也不自动更便宜。
- 有复购商品和可执行权益：优先考虑针对性商品优惠、套餐/随心配承接，结合主菜单价格约束；不要默认全店打折。套餐要核成本、产能和既有订单被折价替代的可能。

**输出：**“目标客群/场景 → 让其买什么 → 为什么这个权益有效 → 从哪个指标验证”。只从工具 A 换到工具 B，不能宣称完成了人群策略。无分群结果时可提出候选试行，但不能给它编收益。

**补数：**若分群 ROI 只含广告而未含让利，索取权益实际承担方、核销和商品成本，说明这会改变主投哪群、保留哪种权益。不要用原经历中的 ROI 数字作本店基准或因果证明。

## 4. 生意诊断 → 策略 → 工具组合，而不是工具排名 → 搬钱

**原打法：**先识别生意问题，再匹配策略及工具/渠道，复盘后迭代。作者也区分了“同样的量买得更便宜”和“改变钱花在谁身上”。

**怎么选：**对主要问题至少比较两个有实质差别的方向，例如修供给与加曝光、改善商品权益与更换流量工具。说明各自解决哪一段瓶颈，以及未选方向为何当前不优先。无投放或承接损坏时，“暂不加预算”可以是正确选择。

预算集中只能触发检查；高占比不等于低效。比较工具先统一周期、归因、成熟退款、自然成交和费用范围，再看边际试行及容量。具备可比边际数据才测算调拨收益；缺数据时给有额度和观察窗口的小试，不把平均 ROI 线性外推。平台名称不同，按曝光、定向触达、点击、商品承接等能力映射，不假定同名同效。

**输出：**所选组合里每个工具负责什么、资源从何处来、保留什么、停止什么；钱数扣齐让利、商品/履约、广告及新增执行成本，不能把总净收入÷广告费叫归因 ROI。补数只问会改变是否调拨、调多少或是否先修承接的关键数据。

## 5. 没有门店指挥权，也要把方案推进到可回传的动作

**原打法：**诊断表给证据，培训给操作方法，城市通报让差距可见，品牌接口人跟进责任，拜访确认下阶段动作。用户负责诊断与推动，品牌/城市执行；不是用户直接管理全部门店。

**怎么做：**给主要动作安排实际可用的责任链：总部确认资源/规则，区域或接口人协调，店长落实营业、商品或排班，财务确认口径。不存在的角色不要编名字；单店直接落到老板或店长。把“做运营优化”改成一次能确认完成的动作。

**输出：**在现有 actions 和 analysis.execution 写清“谁确认什么、谁做什么、何时回传什么记录”。例如总部确认试点范围，店长回传上架/库存或排班记录，财务回传同口径贡献。排名要用可比组与分母，不能拿城市规模当执行能力。

**如何回诊：**先看实际覆盖、投入和偏离。未执行时查是不会操作、缺资源还是无权限，再选培训、协调或调整负责人；已执行但无改善才回到策略。没有回执就明确未核实执行，不把分析建议算成经营成效。沟通频率随执行稳定度变化，不照搬历史每天通报。

**可选共投/JBP：**材料已给平台政策时，列可用资源、商家承诺、条件、时间和实际承担方，再决定是否值得共投。平台现有政策不写成作者发明；条件资源不算已到账，也不自动按历史 1:1 配比。无政策时不索取、不假定能拿补贴。

## 6. 从本人复盘补强：既看利润，也看规模；先验执行，再扩围

原经历反思过“只定义动作，没有定义何时必须做”、保利润却丢规模、试点偏向基础好且配合度高的门店，以及基线、对照和留痕不足。以下是据此增加的当前产品纪律，不冒称当年已经完整执行：

- 每个优先动作同时看贡献与订单/净收入等规模信号，不能靠停业或放弃需求获得表面高利润。短期减量若合理，应说明代价和恢复条件。
- 基线、观察窗口、预算与成功/停止条件来自本店材料和老板目标；没有阈值依据时标为建议试点设置。不能照搬示例中的 4 周、8 周或 30% 等常数。
- 实际增量同时核执行费与费用包含关系。负向更正足以推翻方案时明确撤回；缺一个数只限制相关结论，别把整个报告退回。
- 只有执行记录与可比结果支持，才决定保留、改动或扩围。扩围还核门店需求、能力、权限与试点选择偏差；只挑配合好门店不能代表全品牌。

## 写入本轮记录，不增加客户表单

`analysis.goal` 写目标与收益主体；`chosen_strategy` 交代相关分店/人群选择及资源取舍；`alternatives` 保存未选策略；`execution` 放真实责任链和回传；`assumptions` 放关键限制。仅使用与本店有关的部分，面向老板仍是首屏一句结论、一个钱数、先做的一件事。具体发现、动作、钱数继续各自引用本轮材料和实际计算。

四类 `method_usage` 分别对应分店/场景资源、人群权益、策略工具、执行复盘。写清本轮选择及证据，并关联 findings/actions/charts/money/audience_plan 中实际存在的位置；不是复制这份规则作为采用证明。有人群资料时用 `audience_plan` 展示“给谁、商品、权益、理由、验收”，没有资料就说明该分支缺什么且为何影响决定。产品讲解只展开这些实际记录，内部 ID 不显示给客户。

交付前检查：换另一类店，策略是否会随证据变化；撤去成本/人群数据是否诚实缩小结论；收到反向或未执行证据是否改判。**引用这份文件、写出“四象限”几个字，都不等于实际用了方法。**
