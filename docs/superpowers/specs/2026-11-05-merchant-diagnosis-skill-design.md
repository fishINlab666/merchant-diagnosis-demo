# AI 商户诊断 Skill 设计

日期：2026-11-05
状态：按最新反馈重构交付物

## 1. 目标

交付一个可独立运行的商户诊断 Skill，而不是网页演示。输入店铺页公开信息和一份或多份 CSV／XLSX，真实调用 Kimi 完成表格语义理解、公开初诊、数据索取和完整经营方案。模型必须实际参与生成，不允许用预置答案冒充 AI 成功。

## 2. 核心原则

- AI 负责语义和判断：识别不同表头、表结构、指标含义、公开问题、经营解释和方案表达。
- 程序负责事实和计算：读取原始单元格、应用 AI 映射、聚合数据、检查门店身份、复算 GMV／毛利和记录 token。
- 缺少数据时降级可开放模块，不补造数字。模型或 API 失败时明确失败，不回落到固定答案。
- 客户工作流为“初步判断 → 为什么值得继续 → 需要什么数据 → 完整方案”。公开阶段有观点但不装确定，完整阶段才给确定动作。
- 边界提醒集中出现一次，不在每张卡片重复“不是收益承诺”“不是已证实结论”。

## 3. 工作流

### A. 公开初诊

输入公开文本。AI 输出有生意感的标题、最多 3 个“观察 → 为什么重要 → 下一步核查”、数据索取清单和一句边界说明。禁止输出内部 ROI、预算和收益结论。

### B. AI 表格理解

读取每个文件／工作表的表头和样本行。AI 返回表粒度、原字段到标准字段的映射、缺失字段和说明。程序只接受白名单标准字段，并从原始行生成门店周报；多门店文件要求分开运行，避免静默混店。

支持：不同中英文表头、多个文件、多个 sheet、汇总表与工具明细表、金额和百分比常见格式。真正缺失的字段进入缺口清单，不由模型补值。

### C. 完整方案

AI 结合公开初诊、映射摘要和真实周报生成最多 3 个问题、预算建议、测算假设、三句话和 3 项跟进动作。程序验证工具名称、调整金额和归因边界，并复算可开放的 GMV／毛利场景。不能复算时保留数据解释但标记未测算。

### D. 运行证据

每次运行输出公开初诊、映射预览、完整方案、结构化结果和运行元数据。元数据记录真实 provider、model、API 调用次数、token 用量、输入文件、映射缺口和计算警告；不记录 API Key。

## 4. Skill 结构

项目级路径：`.agents/skills/merchant-diagnosis/`

- `SKILL.md`：触发条件、工作流、真实 AI 约束和输出要求。
- `scripts/llm_client.py`：Kimi Chat Completions、JSON 解析、错误和用量。
- `scripts/file_readers.py`：CSV／XLSX 多表读取和隐私友好的样本预览。
- `scripts/pipeline.py`：公开初诊、AI 映射、数据聚合、完整方案和复算。
- `scripts/diagnose.py`：命令行入口。
- `references/methodology.md`：商户诊断方法和客户表达。
- `references/schemas.md`：标准字段和结构化输出。
- `assets/public-shop.txt`、`assets/demo-weekly.csv`：明确标注的合成验收数据。
- `evals/test_pipeline.py`：离线逻辑测试；`evals/live_smoke.py`：真实 Kimi 调用验收。

最终打包 `merchant-diagnosis.skill`，但不在未确认的情况下宣称已安装到全局技能目录。

## 5. 模型配置

优先使用现有 `KIMI_API_KEY` 和 `KIMI_BASE_URL`，兼容 `MOONSHOT_API_KEY`；模型可由 `KIMI_MODEL` 覆盖，默认 `kimi-k3.1-pro`。使用官方 Chat Completions JSON Mode。测试只使用合成或脱敏数据。

## 6. 验收

- 单元测试覆盖 CSV 变体、XLSX 多 sheet、AI 映射应用、缺失字段、多门店阻断、计算和错误不回落。
- 真实 Kimi 调用覆盖公开初诊、表头映射、完整方案三阶段，保留 token 证据。
- 输出不得包含预置回答、虚构历史或重复免责声明；映射结果必须能追溯原始表头。
- Skill 结构和打包校验通过，命令行可直接运行。
