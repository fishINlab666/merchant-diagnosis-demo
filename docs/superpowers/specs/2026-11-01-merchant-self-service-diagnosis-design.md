# 商家自助经营诊断工具设计（A＋B 整合）

- 日期：2026-11-01
- 状态：方向已确认
- 依据：导师“做成工具、输入店名、可复用到很多商家、只做商家一类”的反馈；Jim 阿里与朴朴项目卡；既有诊断设计书

## 1. 产品定位

面向餐饮外卖商家老板、外卖负责人和门店运营。使用者输入自己的店名后，工具先尝试检索公开信息并生成公开初诊；检索失败或证据不足时，转为人工补充公开信息。上传一份平台周报后，生成完整经营诊断和下一周行动方案。

首个细分只做餐饮外卖单店，不做品牌多门店、跨平台归因、平台 KA／服务商／SaaS 客户成功三种角色视图。

## 2. 主流程

1. **店名建档**：店名必填；平台、城市／商圈、品类、价格带用于缩小检索和样本范围。
2. **公开信息获取**：店名触发公开检索；同时保留评分、菜单、价格、评价等人工补充入口。
3. **公开信息初诊**：展示来源、采集日期、公开事实、待验证假设和补充数据清单。
4. **周报完整诊断**：本地解析一份 CSV／XLSX，按数据完整度开放经营、流量、投放、补贴和用户模块。
5. **下一周行动方案**：最多三个主动作，每项带负责人、复核指标、目标、日期和停止条件。
6. **试用示例**：合成案例只作为可选演示，不作为默认页面或真实商家结论。

## 3. A＋B 数据链路

### B：公开检索适配层

- 输入店名及可选城市、平台、品类，生成检索请求。
- 优先尝试公共网页读取适配器；返回内容必须保留来源标题、URL、采集时间和原文摘要。
- 适配器不可用时显示真实错误，并自动打开人工补充，不显示“搜索成功”。
- 检索内容只支持公开初诊，不据此生成曝光、P1、P2、ROI、利润或续费结论。
- 可插拔支持后续服务端搜索代理或 Exa 等来源；前端不得内置任何密钥。

### A：人工补充与授权周报

- 评分、菜单观察、价格带、典型评价等公开字段可人工确认或修正。
- 周报只在本机解析和计算，不发送给公共检索服务。
- 真实上传数据不绑定合成 SaaS 使用数据，不绑定主案例竞店结论。

## 4. 经历方法论固化

### 4.1 诊断顺序

1. 门店、平台、窗口和指标口径检查。
2. 订单、净 GMV、净客单、补贴和经营贡献。
3. 曝光 → P1 进店 → P2 下单，区分自然与付费曝光（有字段时）。
4. 分工具消耗、归因 GMV、ROI 和工具集中度，先检查归因定义、窗口与成熟度。
5. 菜品、套餐、价格带、评分与典型评价，区分事实和候选原因。
6. 复购、会员、购买频次×生命周期；不冒称 RFM，不把人群简单加总。
7. 有同口径门店／城市数据时才做 UE×增速分层；单店缺数据时不展示虚假分层。

### 4.2 决策规则

- 规模与利润同看，过程指标改善不等于经营改善。
- 原工具是基本盘时，只建议增量预算小步测试，不全量切换。
- 曝光问题、P1 问题、P2 问题和利润问题不得混成一个“加投放”建议。
- 动作绑定证据、负责人、复核指标、基线／对照和停止条件。
- 低 UE×低增长且连续无改善时才执行资源退出；只有一周数据时不套用连续 4／8 周规则。
- 竞店不足或口径不一致时只展示样本事实，不输出行业均值或排名。

### 4.3 商家输出

- 我的店现在怎么样：核心经营事实和数据覆盖。
- 钱漏在哪：最多三个优先问题及关键数字。
- 为什么：支持证据、候选原因、反证和缺口。
- 下周先做什么：最多三个主动作及停止条件。
- 调整可能值多少：仅在有完整假设时计算，明确是测算不是承诺。

## 5. 页面调整

- 首屏为店名输入与“开始经营诊断”，不再默认加载合成品牌。
- 删除平台 KA／服务商／SaaS 客户成功切换及角色专属页面。
- 公开初诊在周报上传前即可查看，周报上传后无缝升级为完整诊断。
- 页面主文案统一为商家视角：“我的店怎么样、钱漏在哪、下周先改什么”。
- 保留现有红色／米白／黑视觉、移动优先报告和打印能力。

## 6. 通用性与验收

至少三类合成店铺：

1. 数据完整的中式快餐单店：能跑完整六维诊断与预算测算。
2. 高客单正餐单店：不能只复用低客单快餐动作，重点检查菜品、价格带和利润。
3. 缺流量／用户字段或归因不一致的单店：只开放合格模块，不机械输出同一建议。

公开检索验收：成功、无结果、超时、跨域失败、无来源文本均不得伪造事实；失败可转人工并继续周报诊断。

结构验收：更换店名、品类、价格带和周报后，事实、指标、问题与动作由输入驱动；任意两店不得仅替换店名而得到完全相同的诊断文本。
