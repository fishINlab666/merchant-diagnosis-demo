# 三种角色决策视图重构设计

- 日期：2026-10-31
- 状态：方向已确认，进入实现
- 依据：导师反馈、Demo 1 一页需求 v2、经营全景第二视图设计、上一轮角色视图 BLOCK 审查

## 1. 核心原则

三种角色共用同一份经营事实、竞店样本、归因规则和预算测算，不复制三套经营算法。角色切换必须同时改变：

1. 决策问题与页面标题。
2. 六维分析的展示优先级和角色解释。
3. 至少一个完整的角色决策模块及其指标。
4. 输出板块标题、话术和跟进动作。

只修改角色横幅、角色标识或三句话术，不满足验收。

## 2. 角色决策模型

### 平台 KA：预算与 JBP

- 核心问题：钱漏在哪、预算怎么调、哪些门店或城市加码／收缩。
- 六维顺序：商业化结构 → 补贴与毛利 → 流量承接 → 城市与门店分层 → 门店基建 → 用户经营。
- 决策模块：JBP 与预算分层，展示可调整问题、预算动作、GMV／毛利测算或阻断原因。
- 跟进：商家预算执行、实际 ROI、净 GMV、毛利和下周 JBP 决策。

### 服务商：获客与交付

- 核心问题：用哪个问题开启客户沟通、本周交付什么、如何留下可复核的服务证据。
- 六维顺序：门店基建 → 流量承接 → 补贴与毛利 → 用户经营 → 商业化结构 → 城市与门店分层。
- 决策模块：新客沟通与本周交付包，展示首聊钩子、三项交付动作、客户复核证据。
- 跟进：客户确认问题、服务动作完成、前后数据复核；未执行不得包装成客户案例。

### SaaS 客户成功：健康与续费干预

- 核心问题：客户出现了哪些经营与使用风险信号、何时干预、复核后是否解除。
- 六维顺序：用户经营 → 补贴与毛利 → 流量承接 → 商业化结构 → 门店基建 → 城市与门店分层。
- 决策模块：客户健康与续费干预，展示经营风险信号、产品使用深度、干预优先级和复核日期。
- 跟进：经营干预、周报导入／结果回填、续费风险复核。
- 风险等级只作为规则化的干预提醒，不表达续费概率或因果预测。

## 3. 数据边界

- 经营风险信号来自现有六维分析的 `risk`／`watch` 状态，基础事实在三个角色中保持一致。
- SaaS 使用行为是独立输入，不从 GMV、ROI 或补贴推断。
- 主合成案例附明确标注的合成使用数据：活跃操作员、周报导入、跟进回填率、最近活跃日期和续费复核日期。
- 真实上传周报或未提供使用数据的案例，客户成功模块显示“未提供”，只输出经营风险和补数据动作，不生成续费风险等级。
- 归因口径不一致或窗口未成熟时，继续阻止 ROI 排名和预算测算；三种角色保留各自的解释与行动，不绕过硬边界。

## 4. 组件与数据流

新增纯函数 `buildRolePerspective`：输入角色、周报、经营全景结果、预算诊断结果和可选产品使用数据，输出：

- 页面标题、决策问题和摘要。
- 三项角色决策指标。
- 带角色解释的六维排序结果。
- 角色决策模块。
- 角色化的竞店／城市模块说明。

新增 `RoleDecisionPanel` 组件，在经营全景和预算方案中复用同一角色决策证据，避免两个视图互相矛盾。

`buildDiagnosis` 继续负责确定性计算，并新增：角色化问题排序、角色化跟进表、全部分支均保留角色话术。基础 `calculation` 不随角色变化。

经营全景增加角色化“下一步动作”；预算方案保留原四块主流程，但根据角色改为预算沟通、客户交付或健康干预语义。

## 5. 验收契约

1. 同一输入下，三种角色的六维原始事实和预算测算完全一致。
2. 三种角色的六维顺序、角色决策模块 ID、决策指标和跟进动作存在结构性差异。
3. 服务商必须同时出现获客钩子、交付动作和客户复核证据。
4. 客户成功必须同时出现经营风险、产品使用深度和干预复核；缺使用数据时明确降级。
5. 平台 KA 必须保留预算调整、JBP 和门店／城市资源决策。
6. 主案例、对照案例、利润风险和归因异常场景均执行角色结构断言，不能只检查文案关键词。
7. 桌面、移动端和打印视图均能看见角色决策模块，不引入横向滚动或无关视觉装饰。
