# 分步演示分析流程设计

- 日期：2026-11-01
- 状态：用户已确认方向

## 目标

面试展示不再直接进入报告，而是呈现“预填数据 → 下一步 → 分析过程 → 查看结果”的真实工作流。正常商家上传路径保持不变。

## 流程

1. **演示门店信息**：预填明确标注的合成门店档案、门店 ID、平台、城市、品类、价格带、评分和菜单观察。
2. **预填周报与映射**：展示 `main-weekly.csv`、文件门店 ID 和可确认的字段映射，不要求用户实际上传文件。
3. **逐步分析**：依次展示数据校验、经营结果、流量承接、商业化与利润、用户与竞店、生成动作六步。每步显示运行中／完成状态和由真实计算得到的证据。
4. **查看结果**：分析完成后进入现有经营诊断与行动方案。

## 规则

- 阶段证据必须来自 `mainCase`、`buildDiagnosis` 和 `analyzeBusinessHealth`，不写死展示数字。
- 计算在本地完成，阶段逐步揭示只是呈现方式，不包装成云端 AI 作业。
- 支持减少动态效果偏好；分析中禁用重复启动，完成后允许重新查看。
- 演示数据全程标注合成，不与真实上传混淆。

## 验收

- 不上传文件也能完成演示。
- 每一步有真实证据和明确状态，最后进入现有诊断结果。
- 桌面、移动、既有上传与映射流程不回归。
