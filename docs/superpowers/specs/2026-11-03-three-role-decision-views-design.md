# 商家老板／平台 KA／SaaS 客户成功三角色决策视图设计

日期：2026-11-03
状态：按用户指定方向落地

## 1. 目标与验收

在现有单店诊断工具上恢复三种角色视图。角色切换必须同时改变决策问题、分析顺序、决策指标、专属分析模块、话术与跟进动作；只切换标题或文案不算完成。

三种角色共享同一份周报、经营事实、归因门槛和预算计算。任何角色都不得绕开口径不一致、窗口未成熟、基本盘和毛利风险门槛。

## 2. 方案选择

采用“共享事实层 + 角色决策层 + 角色专属组件”。

不采用纯文案切换，也不完整复刻参考图的 186 家随机门店、虚构续费日期或随机健康分。参考图用于确定信息架构和决策深度，不用于伪造证据。

## 3. 三种角色

### 商家老板

- 决策问题：钱漏在哪、预算怎么调、调完 GMV／毛利如何变化、下周谁执行。
- 保留现有四块：问题、预算与收益、三句话、跟进表。
- 决策模块：本周预算动作、预计净增毛利、停止条件。

### 平台 KA

- 决策问题：如何用预算结构调整和经营证据推进 JBP，哪些城市／门店加码或先修。
- 分析顺序：商业化结构 → 补贴与毛利 → 流量承接 → 城市／门店分层 → 门店基建 → 用户经营。
- 专属模块：JBP 预算沟通指标，以及“增长 × UE”城市分层散点／四象限和分层动作表。
- 分层使用现有 4 个合成城市样本，明确标注样本数；真实周报没有同口径样本时显示数据缺口，不生成城市排名。
- 输出：预算沟通话术、JBP 复核、城市资源动作。

### SaaS 客户成功

- 决策问题：客户有哪些经营与使用风险、何时干预、复核后是否解除。
- 分析顺序：用户经营 → 补贴与毛利 → 流量承接 → 商业化结构 → 门店基建 → 城市／门店分层。
- 专属模块：客户健康度仪表、风险信号表和干预复核。
- 信号包括经营回报、补贴依赖、周报导入、跟进回填、最近活跃和续费复核窗口。
- 健康分只是规则化的干预优先级，不是续费概率或因果预测；计算规则在页面可查看。
- 主合成案例带明确标注的产品使用数据。真实周报未提供使用数据时，健康分显示“--”，相关行显示“未提供”，只呈现有证据的经营风险和补数据动作。

## 4. 数据模型与边界

新增 `ProductUsage` 可选字段：活跃操作员、周报导入次数、跟进回填率、最近活跃日期、续费复核日期。它独立于 GMV／ROI，不从经营结果反推。

新增纯函数：

- `buildRolePerspective(role, report, health, diagnosis)`：产出角色标题、指标、六维顺序、角色模块、话术和动作。
- `buildCitySegments(cities)`：把城市增长与 UE 映射到加码、稳住、调结构、收缩整改。
- `buildCustomerHealth(report, health, usage?)`：在有完整使用数据时计算健康分，并始终区分已知事实与缺失信号。

保留现有 `buildMerchantPerspective` 作为商家老板兼容入口。`buildDiagnosis` 增加 `merchant` 角色别名，既有 `ka／agency／cs` 测试和计算行为保持兼容；UI 只展示商家老板、平台 KA、SaaS 客户成功三项。

## 5. 组件与交互

- 顶部增加三角色切换，选中状态使用 `aria-pressed`，切换不丢失当前周报、视图和测算假设。
- `RoleDecisionPanel` 复用角色决策模型，替换当前只支持商家老板的固定文案。
- `ReportView` 按角色插入 `CitySegmentation` 或 `CustomerHealth`；老板版不插入这两个模块。
- `BusinessHealthView` 的六维排序、决策指标和跟进动作随角色变化。
- 话术标题分别变为给老板、给品牌方、给客户的三句话。
- 延续 Google 四色扁平视觉，移动端单列，键盘可操作。

## 6. 测试与验收

- 单元测试：三种角色结构差异、共享计算一致、KA 四象限、CS 健康分与缺失降级、异常归因分支。
- 浏览器测试：逐一切换三个角色，断言专属模块和表格内容，而非只检查标题；验证角色切换后测算不变。
- 数据边界：真实上传不出现合成城市、合成使用数据或续费评分。
- 视觉验收：桌面、390px 手机、键盘焦点、角色专属模块和 A4 打印。
- 全量执行 lint、单元测试、构建、E2E、业务 EVALS，之后合并 main、部署并在线逐一验证三种角色。
